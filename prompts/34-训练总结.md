# 训练总结 · 专职规则

> 本文件**只给训练模式用**（`solve/training.py`）。它与读题 / 标定 / 收尾确认
> 是**四份互不相干的契约** —— 一次请求只喂一个，别把它们混在一起。
>
> 你的输入是**一次已经成功跑完的任务的运行记录摘要**（事件流 + 每题的读题与作答留痕）。
> 你的产出是**几条可以写进下次提示词的判读经验**，不是复盘文章。

---

## 输出格式

严格只输出一个 JSON 对象。不要解释、不要 markdown 代码块、不要多余文字。

```json
{
  "vision": ["读题经验：什么样的画面特征会让抄录出错，下次该注意什么"],
  "solver": ["解题经验：这类题型的作答要点 / 常见的作答陷阱"],
  "advance": ["推进经验：这类页面形态下，进入下一题的方式与坑"],
  "skipped": "这次记录不足以总结时，在这里说明缺什么；能总结就给 null"
}
```

| 字段 | 规则 |
|---|---|
| `vision` | 给**视觉组**（`10-视觉组.md`）的经验。0~3 条 |
| `solver` | 给**解题组**（`20-解题组.md`）的经验。0~3 条 |
| `advance` | 给**下一题方式库**（`33-推进方式库.md`）的经验。0~3 条 |
| `skipped` | 记录不够（例如没有异常、没有推进动作）就如实说明；正常给 `null` |

---

## 什么才算「经验」

**写机制，不写结论；写可复用的判读要点，不写这道题的答案。**

✅ 该写：

- 「一屏里第 2 道题的题干常常紧贴第一屏底边，抄录时要检查它有没有被切掉半行」
- 「选项框给得比文字宽时，下游按内容质心点；坐标贴近文字本身更稳」
- 「长卷页面里题号不连续是正常的（题库编号稀疏），不要因为跨度 > 1 就判成漏题」

❌ 不该写：

- 「第 3 题的答案是 B」——**答案不能进提示词**（会污染 qid，也会让下一次「抄自己」）
- 「这次花了 12 次调用」——那是运行统计，不是判读经验
- 「要注意认真一点」——空话，模型照做不了

---

## 硬约束

- **一条经验一句话**，能直接照做；不要写成段落。
- 宁少勿滥：没有值得写的就返回空数组 `[]`，**不要为了凑数编经验**。
- **绝不写具体题目的答案、选项内容或题目文本**。
- 不写与「看画面」无关的东西（网络、磁盘、耗时、token 数）。
- 中文，每条不超过 60 字。
