# 共享契约

> 本文件由**两个模型共同阅读**。它规定两边怎么合作、中间那份数据长什么样、以及哪些事两边都不许做。
> 你的专职规则在另外两份文件里：
> - 视觉组 → `10-视觉组.md`
> - 解题组 → `20-解题组.md`

---

## 1. 分工

| | 视觉组 | 解题组 |
|---|---|---|
| 职责 | **看见** —— 把画面如实转成结构化题目与页面观测 | **算对** —— 拿结构化题目给出答案 |
| 输入 | 网页/窗口的截图（一屏） | 结构化题目（纯文本，数学写成 LaTeX） |
| 输出 | 题目 JSON + 页面观测 JSON（含几何与质量字段） | `{"chosen_labels": ["A"], "confidence": 0.9, "reason": "..."}` |
| **绝不** | 作答、把答案写进题干、替程序决定「该怎么翻页」 | 改题面、改标号、看坐标或图片判题 |

**全链路只有一份题面。** 解题组看到的题面，就是视觉组抄出来的那一份。
所以：**视觉组抄错 = 解题组必然算错，而这个过程不会报错。**
两边都按这个前提行事。

**解题组只吃文本。** 它拿到的永远是那份抄录下来的题面（纯文本 + LaTeX），
**拿不到截图、拿不到坐标、也拿不到任何图片**。这条分工不是建议，是硬约束：
一旦让解题组看到图，两份模型就各自"看见"了一份题面，而它们**不一致时没有任何人会发现**。

## 2. 中间数据：题目 JSON

视觉组产出、编排层传给解题组的那份数据。

**一屏可能有多道题**（长页面上很常见），所以视觉组的产出是一个**数组** ——
下游会一次把整屏都拿走，后面的题不必再截一次图、再调一次模型。

```json
{
  "page": {
    "progress": "16 / 44 题",
    "total": 44,
    "current": 16,
    "next_control": {"box": [x, y, w, h], "label": "下一题"},
    "card": {"box": [x, y, w, h], "cols": 5, "rows": 9,
             "current_box": [x, y, w, h], "next_box": [x, y, w, h]},
    "submit": {"box": [x, y, w, h], "scope": "question | paper"},
    "completed": "all_done | not_done | unknown",
    "scrolling": true,
    "reason": "一句话依据"
  },
  "questions": [
    {
      "index": 1,
      "num_text": "1.",
      "qtype": "single | multiple | text | unknown",
      "stem": "题干全文，数学写成 $...$",
      "formulas": [{"span": "$f(x)$", "box": [x, y, w, h]}],
      "options": [
        {"label": "A", "text": "选项正文，数学写成 $...$", "box": [x, y, w, h]}
      ],
      "clipped": ["stem", "option:D"],
      "uncertain": ["option:D", "stem.formula.1"],
      "note": "一句话说明依据或异常"
    }
  ],
  "more_below": true,
  "note": "本屏共 2 道完整题目"
}
```

**被切掉半截的题不进 `questions`** —— 下游拿到的每一道都必须能独立作答。

**`page` 是观测，不是决定。** 视觉组只报告「画面上有什么」（哪个控件、哪个网格、
进度文字写的是什么、提交按钮管多大范围）；「用哪一条推进逻辑、什么时候提交、
什么时候算做完」由**程序**在开局按固定规则裁决一次，之后整条运行都按它执行。

**唯一的例外是「这一步的推进落点」**（2026-10-01 加）：视觉组在
`page.advance_skill_id` 里选一个**推进技能**（`advance_click` / `advance_swipe` /
`advance_card`），并用 `page.next_control.box` / `page.card.next_box` / `page.swipe`
给出**当前这一屏**的落点。这不是「把控制流交给模型」—— 方式、提交时机、收尾判据
仍然全在程序手里；视觉组只回答「按这张画面，那个入口在哪 / 该滑多远」，
而且**每一屏都要重新答一次**（复用上一屏的坐标就会点偏）。

**字段归属**（哪些给谁）：

| 字段 | 视觉组 | 解题组 | 编排层（不是你俩） |
|---|---|---|---|
| `qtype` / `stem` / `options[].label` / `options[].text` | 产出 | **读**（这是解题组唯一能看到的内容） | 转成题目下传 |
| `options[].box` / `formulas[].box` | 产出 | **看不到** | 交给执行层按坐标点击 |
| `page` 整块（`progress` / `total` / `current` / `next_control` / `card` / `submit` / `completed` / `scrolling` / `advance_skill_id` / `swipe`） | 产出 | **看不到**（跟解题无关） | **开局裁决**推进方式与提交范围、收尾判据；**每一步**按视觉组给的落点执行 |
| `page.submit.scope` | 产出 | **看不到** | **决定提交时机**：`paper` → 推迟到全部题做完的收尾；`question` → 每题提交。判错会提前交卷，见 `10-视觉组.md` |
| `page.card` / `page.next_control` / `page.swipe` | 产出 | **看不到** | **推进落点**：优先用**本屏刚给**的这些观测；拿不到才退回开局几何（答题卡按题号推算） |
| `clipped` / `uncertain` | 产出 | **看不到** | **门禁**：不通过就不下传，先重读或停下来问人 |
| `more_below`（顶层） | 产出 | **看不到** | 只作提示（下方还有内容），**不拦** |
| `index` / `num_text` | 产出 | **看不到** | 用来判断「推进之后是不是真的换了题」（发现跳题） |
| 题目指纹 `qid` | **不用产出**（下游自己算） | **看不到** | 编排层按题干哈希，用于对账与缓存（见 §4） |

**结论：解题组只会收到一份"已经过门禁的题面"。**
门禁的结果，解题组是从题面里感受到的 —— 如果某个公式没能读出，
题面里会出现 `$?$`，并且消息里会有一行缺失提示。
**解题组不需要、也拿不到 `clipped` / `uncertain` 这些中间字段。**

> 如果门禁发现题面残缺，正确动作是**不下传**（先重读、或停下来问人），
> 而不是"把残缺的题交给解题组让它自己小心"。

## 3. LaTeX 约定（两边必须口径一致）

1. **所有数学内容一律写成行内 LaTeX，用 `$...$` 包起来**，保持它在句子里的原始位置。
2. **区间 / 集合用 `[a,b]`、`(a,b)`、`[a,b)` 这类写法。**
   **禁止**用 `bmatrix` / `matrix` / `pmatrix` / `cases` 去凑一个区间或集合
   —— 那不是矩阵，凑出来两边一定读错。
3. **严格区分大小写**：`p` 与 `P`、`x` 与 `X`、`y` 与 `Y`、`a` 与 `A` 是完全不同的符号。
   - 视觉组：按图中**实际字形**写。
   - 解题组：按**字面**理解，**不得**"顺手纠正"成更常见的那个符号。
4. **`$?$` 表示"该处公式未能读出"。**
   - 视觉组：写不出来就用 `$?$` 占位，并把位置加进 `clipped`。**绝不编。**
   - 解题组：见到 `$?$` **不得作答**（见 §5）。
5. 解题组**不得**改写、简化、重新排版题干里的 LaTeX。

## 4. 标号与题目指纹

1. `options[].label` 是**页面标号**（页面上印的 A/B/C/D）。
2. **解题组看到的标号，就是页面标号，一一对应。** 编排层**不打乱、不重排、不改写**
   选项顺序 —— 视觉组抄下来的顺序，就是解题组读到的顺序。
   （这条以前是反的：编排层会重排选项、把位置字母当成标号呈现给解题组，
   而解题组被明确告知"你看到的就是页面标号" —— 两边对同一件事的说法互相矛盾，
   真机上表现为"模型说 D、程序落在 C"。现在只有一种口径。）
3. 解题组只回**字母**，不回选项正文；最多给多个字母（多选）。
   若视觉组给的标号不连续（例如某选项没能读出、只剩 A、B、D），
   **照它给的字母回**，不要自己补 C。
4. 计票按**内容**比对：字母对得上但选项正文对不上，**不算同一票**。
5. `qid = sha1(NFKC(题干) + 排序(选项正文))[:16]`，**不含任何答案信息**。
   - **由编排层按题干自己算**（视觉组**不需要**在产出里写它 —— 让它算只会白占篇幅、还容易算错）。
   - 它是**编排层的对账键**：把「读到的题」与「解的题」绑在一起。
   - 所以解题组**看得到它**（消息里那一行 `题目ID:`），但**不需要在回复里回报它** ——
     它收到的题面与 `qid` 同源，编排层自己就能对上。
   - 推论：解题组**不得改写**题干与选项正文，改了就等于换了指纹。
     （这条护栏的另一半在视觉组那边：照实抄，不要为了指纹好看而调整题干。）

## 5. 不确定时的统一处置

**"不知道"是合法结论，不是失败。两边的唯一义务是把它声明出来，绝不猜。**

| 情形 | 视觉组 | 解题组 |
|---|---|---|
| 某个符号/公式看不清 | 写 `$?$`，位置进 `clipped`，并在 `uncertain` 里点名 | 见到 `$?$` 或缺失提示 → **空作答** |
| 题干或选项被画面边缘切掉 | 记进 `clipped`；**这道题不要放进 `questions`**（下游只收完整题） | 一般收不到这类题；真收到就 **空作答** |
| 画面下方还有题没露全 | 顶层 `more_below: true`（**不拦**，下方还有题是正常形态） | —— |
| 题型判不出来 | `qtype: "unknown"` | —— |
| 题面信息不足以下结论 | —— | **空作答**（`confidence: 0`） |
| 自己拿不准但题面完整 | 把该项写进 `uncertain` | 正常作答，但在 `confidence` 里给低值、并在 `reason` 里写明不确定之处 |

**空作答的写法**：`{"chosen_labels": [], "confidence": 0, "reason": "题面缺失：<缺什么>"}`
空作答的含义是"停下来等人"，下游会因此暂停 —— 这是**正确行为**，不是失败。

**`confidence` 是解题组自报的把握**（0~1）：编排层在**不开启复算**时只能靠它
判断"这个答案值不值得信"。所以它必须诚实：拿不准就给低值，
**不要为了显得确定而写 0.9** —— 那会让下游把一个猜测当成可靠答案提交上去。

**解题组特别注意**：本题面来自视觉抄录，**可能本身就是错的，而且错误不可见**。
所以**不给"最可能的一项"兜底** —— 猜错时从输出上看不出来，会被当成一次正常作答提交上去。

## 6. 两边共同的禁止事项

1. **不得触碰或使用任何答案来源**：页面上的 `data-answer*` 属性、答案库、解析面板、
   历史提交记录。两边都只能从题面本身推导。
2. **不得"顺手补全"看不见的内容**：少一个选项就是少一个，缺一个指数就是缺一个。
3. **不得改写对方的产出**：视觉组不改题面以外的判断；解题组不改题面。
4. **输出里不得夹带解释性散文**：两边都只输出约定的 JSON（解题组的 `reason` 是唯一
   允许写自然语言的地方，且限一句话）。
5. **不得把"猜测"包装成"事实"**：任何非直接观察到的内容都必须标进 `uncertain`。
