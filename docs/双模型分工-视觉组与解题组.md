## 0. 为什么要分工（一句话）

**两种失败模式完全不同，混在一个模型里就没法设门禁。**

| | 视觉组 | 解题组 |
|---|---|---|
| 职责 | **看见**：把画面变成结构化题目 | **算对**：拿结构化题目给出答案 |
| 典型失败 | 少抄一个负号、把 `3` 看成 `2`、把区间凑成矩阵、把截断题干当完整 | 算错、多选题少选、抄自己 |
| 失败是否可见 | **不可见** —— 输出看起来完全正常 | 通常可见（答非所问/自相矛盾） |
| 兜底手段 | 双读互证 + 裁剪放大复核 + 不确定就标出来 | 投票采样 + 唯一性/回代自检 |
| 必须禁止 | **绝不作答** | **绝不改题面** |

> 本次实测的教训正是第一条：**四个选项的区间全被视觉模型凑成了 `\begin{bmatrix}`，而它没有任何报错。**
> 如果不把「读」和「解」分开、不给读的那一步设门禁，这个错误会一路安静地传到还写成答案。

### 1.1 Pass A —— 整屏读题（结构化抄录 + 页面观测）

```text
你是一台**题目抄录器 + 页面观测器**。你看到的是网页的一屏截图。你要做两件事：
① 把这一屏里的**完整题目**转成结构化数据；② 把这一屏**长什么样**如实报出来。

严格只输出一个 JSON 对象，不要解释、不要 markdown 代码块：

{
  "page": {
    "progress": "16 / 44 题",              // 页面上印的进度文字，原样抄
    "total": 44,                           // 读得出来就填，读不出写 null（不要猜）
    "current": 16,
    "next_control": {"box": [x, y, w, h], "label": "下一题"} | null,
    "card": {"box": [x, y, w, h], "cols": 5, "rows": 9,
             "current_box": [x, y, w, h], "next_box": [x, y, w, h]} | null,
    "submit": {"box": [x, y, w, h], "scope": "question" | "paper"} | null,
    "completed": "all_done" | "not_done" | "unknown",
    "scrolling": true | false | null,
    "reason": "一句话依据（只作留痕，判断不靠它）"
  },
  "questions": [
    {
      "index": 1, "num_text": "1.",
      "qtype": "single" | "multiple" | "text" | "unknown",
      "stem": "题干全文（数学公式写成行内 LaTeX，见下）",
      "formulas": [{"span": "$f(x)$", "box": [x, y, w, h]}],
      "options": [
        {"label": "A", "text": "选项正文（公式同样写成行内 LaTeX）", "box": [x, y, w, h]}
      ],
      "clipped": ["stem" | "option:D" | ...],   // 被画面边缘切掉的部分
      "uncertain": ["stem.formula.1" | "option:D" | ...],  // 你自己拿不准的项
      "note": "一句话说明依据或异常"
    }
  ],
  "more_below": true | false,               // 画面下方是否还有内容被截断
  "note": "本屏共 2 道完整题目"
}

━━ 关于数学公式（最重要，必须遵守）━━
1. **所有数学内容一律写成行内 LaTeX，用 $...$ 包起来**，直接嵌在文字里，
   保持它在句子里的原始位置。例：`设 $f(x)$ 为随机变量 $X$ 的概率密度`。
   **不要**用文字描述公式（"x 的平方的三次方根"这种下游没法算）。
2. **区间/集合就用 `[a,b]`、`(a,b)`、`[a,b)`**。
   **绝对禁止**用 bmatrix / matrix / pmatrix / cases 去凑一个区间或集合
   —— 那不是矩阵，凑出来的结果下游一定读错。
3. **严格区分大小写**：`p` 与 `P`、`x` 与 `X`、`y` 与 `Y`、`a` 与 `A`
   是完全不同的符号。按图中**实际字形**写，不要按"看起来更像哪个"写。
4. **不认识的符号原样保留**：写不出来就用 `$?$` 占位，**并把该位置加进 `clipped`**。
5. 只转写。**不计算、不化简、不补充、不给答案、不提示哪个选项对。**
   你一旦把答案写进题干，下游的解题就变成了抄你自己，而且会污染题目指纹。

━━ 关于几何（坐标）━━
6. `box` 是**归一化**坐标：左上角 (0,0)、右下角 (1,1)，格式 `[x, y, 宽, 高]`，
   三位小数。框住该元素**可点击的整行区域**（含标号）。
7. **看不到就写 null，绝不编坐标。** 编出来的坐标会让下游去点一个不存在的位置
   —— 那是一次真实的误操作。页面上没有提交按钮就 `"submit": null`。

━━ 关于 page 块（报告「有什么」，不要报告「该怎么办」）━━
8. `page` **每次都要给**（哪怕什么都没观测到，也要给全字段、用 null）。
   它报告的是画面事实：进度文字、那个固定的「下一题 / 下一页 / 继续」控件、
   题号答题卡、提交按钮及其范围、是否已经全部答完、页面还能不能滚。
   **不要**写「应该点哪里比较好」「现在该不该提交」—— 那是程序侧的事。
9. **答题卡 ≠ 选项列表。** 答题卡里的每一格只有一个**题号数字**（1、2、3…），
   点它只会跳到那道题，不会作答。把选项列表当成答题卡，会让下游一按就跳到别的题。
   `current_box` 是下游对齐整个网格的**锚点**，给歪了整片网格都会歪。
10. `submit.scope` 判错就是事故：`"question"` = 只提交当前这道题；`"paper"` = 提交整份试卷/作业。
    **把 `"paper"` 报成 `"question"`，程序就会做完第 1 题去交卷** —— 判不出来给 `null`，
    拿不准时**往「整卷」那边靠**。

━━ 关于画面边界（第二重要）━━
11. 你只能看见这一屏。**题干或某个选项被画面边缘切掉时，必须把它写进那一道题的 `clipped`**，
    并把 `more_below` 置 true。
    **绝对不要把被切掉的题面当成完整题面交出去**，也**不要让残缺题进 `questions`** ——
    那不会报错，只会让下游拿一份残缺的题去解题，而所有人都以为它是完整的。
12. 画面里有多道题时，**把这一屏里所有完整的题目都抄进 `questions`**（按从上到下排序），
    下游会一次拿走全部，不必为每道题再截一次图。
    （2026-09-28 之前写的是「只抄最靠上的那一道」—— 那会让同屏其余题多花一次模型调用。）

━━ 关于题型 ━━
13. 只有一个正确选项写 `single`；"多选""不定项"写 `multiple`；
    需要在输入框/编辑器里作答（填空、简答、计算、论述）写 `text`；
    判断不了写 `unknown`。
    **如实标注**，不要为了"能答"而把填空题套成单选 —— 下游的执行器只会点选项，
    套成单选的结果是它去找根本不存在的选项然后误点。
14. 即使题型是 `text`（本项目不会自动作答），**题干也照样要抄全**：
    人工需要它。

输出示例：
{"page":{"progress":"1 / 5 题","total":5,"current":1,
 "next_control":null,
 "card":{"box":[0.01,0.10,0.16,0.60],"cols":5,"rows":1,
         "current_box":[0.01,0.12,0.028,0.05],"next_box":[0.04,0.12,0.028,0.05]},
```

### 1.2 Pass B —— 逐项复核（只做一件事：把**决定答案的那个字形**钉死）

> Pass A 一定会出错，而且不会报错。所以对**可能影响答案**的项必须再读一遍。
> 复核的输入不是整屏图，而是**裁剪后放大 3~5 倍的单元素小图**。

```text
用户在核对一段数学表达式。你只能看，不能改。

严格输出 JSON：
{
  "latex": "用最简 LaTeX 原样转写（行内公式）",
  "desc":  "用一句中文把这个式子读出来（逐个符号念，含大小写）",
  "marks": {
    "signs":     ["画面里出现的运算符：+ - = < > ≤ ≥ ∫ lim ∑ √ 等，按出现顺序"],
    "supersub":  ["上标/下标，逐个写出，例如 \"上标:2\"、\"下标:x→∞\""],
    "root_index": "几次方根（数字）；没有根号写 null",
    "exponent_of_x": "字母 x 的指数（数字）；没有写 1",
    "letters":   ["画面里出现的英文字母，从左到右，严格区分大小写"],
    "interval":  "如果是区间，写出端点与开闭，例如 \"[-π/2, 0] 闭区间\"；不是写 null"
  }
}

规矩：
1. 区间/集合用 [a,b]、(a,b) 写法，**禁止** bmatrix/matrix/pmatrix/cases 凑区间。
2. 严格区分大小写：p≠P、x≠X、y≠Y、a≠A。
3. 只转写，不计算、不化简、不补充。
4. 看不清就写 "看不清"、并置 null，**绝对不要猜**。
5. 只输出 JSON，不要解释、不要 markdown 代码块。
```

**两次调用怎么用（门禁规则）**

| Pass A 的 `latex` 与 Pass B 的 `latex` | 判定 | 动作 |
|---|---|---|
| 一致，且 Pass B 的 `desc`/`marks` 也对得上 | `agree=true` | 放行 |
| 不一致 | **冲突** | 第三次复核（换裁剪范围 / 换放大倍数 / 换提问角度） |
| 第三次仍冲突 | **不可判** | 写进 `uncertain`，**门禁拦住**，由编排层停下来问人（`paused_for_dump`） |

> 实测：本次第 2 题题干的负号、第 4 题的上标 2/3、第 5 题的分母指数，
> 都是靠这一级才定下来的。**只看 Pass A 会做错其中至少两道。**

### 1.3 相对现有 `READ_SYSTEM_PROMPT` 补了什么

| # | 补的东西 | 为什么（本次实测） |
|---|---|---|
| 1 | **公式必须转行内 LaTeX** | 原提示词只写"题干全文"，模型会漏掉或只用文字描述；下游拿到残缺题干 |
| 2 | **禁止用矩阵环境凑区间/集合** | 实测四个选项区间**全部**被凑成 `bmatrix`，四个全不可信 |
| 3 | **强制区分大小写** | 第 3 题要填的是小写 `p`；读成 `P` 题意就变了 |
| 4 | **`clipped` / `more_below`** | 视口截断**不报错**，会把半道题当完整题交出去 —— 原契约没有这个出口 |
| 5 | **`uncertain[]` 显式声明** | 视觉模型的置信度校准很差；让它"标出拿不准的项"比让它"报个置信度"实用得多 |
| 6 | **`note` 给依据** | 排障时唯一能回答"它当时凭什么这么读"的字段 |
| 7 | **`text` 题型仍要抄全题干** | 本项目不会自动作答，但**人工需要题面**（本次 3/5 题是这一类） |
| 8 | **两段式（Pass A / Pass B）+ 门禁** | 单次读题无法自证；两次独立读 + 冲突升级，是唯一能压住"读错且不报错"的办法 |

## 3. 交接契约：怎么传给解题组

### 3.1 一份产出，两条下游

```text
                    ┌─────────────────────────────────────────┐
   读图产出 ───────►│  页面观测 page（进度 / 控件 / 答题卡 /   │
   （ReadBatch）    │  提交按钮与范围 / 完成与否 / 能否滚动）  │
                    │      └──► 只给**程序**（core/run_plan.py │
                    │           裁决推进方式与提交时机）      │
                    │                                         │
                    │  题目语义：stem / qtype / options[].label+text
                    │      └──► 转成 Question ──► 解题组（只看文本）
                    │                                         │
                    └───►│  几何：options[].box
                           │  + 图尺寸（image_size）
                           └──► 只给执行层（按坐标点击）
```

**几何不进 `Question`** —— 这是既有设计（`core/models.py::ReadResult` 的注释写明了理由）：
两者的**用途**不同、生命周期也不同。`Question` 是跨层共用的**语义**契约（qid 由题干算、
缓存按键是它、解题组只该看到它、留痕与续跑都依赖它），而坐标只对**执行层**有意义。
**v0.2.0 补充**：0.1.0 这里还有半句「DOM 路径用 `Locator` 点选项、根本不需要坐标」——
DOM 题目通道已删除，那条理由不再成立，但隔离本身要留：
把坐标塞进 `Question` 会让「语义」这一层也背上一个只有执行层用得上的概念，
而解题组一旦能看见坐标，就会被诱导去「看着点位判题」。

**2026-09-30 补第三条下游**：`page` 观测同样**不进 `Question`**，它给的是**程序**。
这是这次收口的核心 —— 视觉组只报告「这一屏有什么」，而「用哪种推进方式、什么时候提交」
由程序在开局裁决一次（`core/run_plan.py::derive_plan`），此后全程照那一份方案执行。

### 3.2 逐条规则

| # | 规则 | 依据 |
|---|---|---|
| 1 | 解题组**只收到语义**（`stem`、`qtype`、选项标号+正文），**收不到任何坐标、图片、截图路径**；请求里 `images` 恒为空，且 `Solver._complete` 里有一道**硬闸**（带图直接 `RuntimeError`，不静默发出去） | 坐标对解题无用；传过去只会诱导它"看着点位判题"。发图这条真机上踩过：推理模型会不回答、只烧 token（`content` 留空），**从输出上完全看不出来**，所以要用硬闸而不是"我们记得不加" |
| 2 | `qid = sha1(NFKC(stem) + 排序(选项正文))[:16]`，**不含答案** | 解题组回报**同一个 qid**，两边对得上才认（防「读到的题」≠「解的题」） |
| 3 | 选项标号给的是**页面标号**，且**顺序就是页面顺序** —— 编排层**一律不打乱、不重排** | p6.0 起取消打乱：模型看到的标号 = 页面标号（可能不连续，如 `A、B、D`），作答回的也是页面标号，`_apply` 直接按它取框点击。**打乱是"标号串位"那条历史事故的成因**，取消之后这一类错误从根上没有了 |
| 4 | **LaTeX 原样透传**，`$...$` 一个字都不改 | 禁止下游"把公式渲染成图再让模型看"—— 那会把视觉误差再放大一次 |
| 5 | 没读出来的公式用 `$?$` 占位，**并同时列进 `clipped`** | 不允许解题组看到一份"看起来完整"的题干 |
| 6 | **门禁**（见 §3.3）不通过 → **不下传** | 读完就解，等于把读题错误当成解题错误 |
| 7 | 解题组必须回一个 `confidence`（**不许省略**；空作答写 `0`） | 不开复算时它是唯一的把握来源 —— 低于门限就标 `⚠复核` 停下，见 §4 |

### 3.3 门禁：什么情况下**不许**把题传给解题组

```text
qtype == "unknown"                     → 不下传，先重读
clipped 含 题干 或 任一选项            → 不下传（视口没覆盖到 / 没读出来）；
                                          重读仍缺 → 必停问人（vision_incomplete）
qtype == "text"（填空/简答）           → 本项目不解答：抄全题干 → 直接交人工
uncertain 含「决定答案的字形」           → 不下传，必停问人（vision_uncertain）
   （负号、上标、指数、根指数、
     区间端点、字母大小写）
uncertain 只含几何类项（box 偏移等）    → 可放行（不影响答案），但记进留痕
Pass B 第三次仍冲突                     → 必停问人（paused_for_dump），绝不猜
```

> **`clipped` 是唯一的"缺了什么"出口**：`missing` 已经并进它（见 §6 顶部第 ② 条）。
> 编排层用 `solve/reader.py::gate_read_result` 实施上表前两行 —— 它是**唯一**的读题门禁，
> **不许绕过**（有守门单测）：`clipped` 非空 → `vision_incomplete`；`uncertain` 非空 → `vision_uncertain`；
> 两种都**停下问人**，绝不把缺半截的题传给解题组。
> `more_below`（画面下方还有内容）**不拦** —— 它只说明"还没看完"，不是"读错了"。

> **判据「是否决定答案」怎么定？** 不是靠视觉组自己说，而是靠**变异测试**：
> 把该字形换一个候选值，看答案会不会变。会变 → 必须复核到两读一致。
> 本次第 2 题的负号、第 4 题的上标 2/3 都属于"换一下就换答案"，所以必须钉死。

## 4. 解题组模型的特化提示词（在现有 `SYSTEM_PROMPT` 上补三条）

现有 `SYSTEM_PROMPT`（`solve/prompts.py`，`PROMPT_VERSION = "p6.0"`）四条硬约束**继续有效**：
只输出 JSON、只回字母标号、多选是集合语义、**标号照抄收到的（就是页面标号，不要按位置重排）**。
（p5.0 时第 4 条写的是「不假设标号固定」，那是**打乱时代**的说法；p6.0 取消打乱后
改成了现在这条 —— 标号仍然不保证连续（视觉组可能漏掉某个选项的框），
但「你看到的标号就是页面上的标号」这件事是确定的。）

**新增三条**（专为"上游是视觉读题"这个场景）：

```text
7. 题干与选项里的 $...$ 是 LaTeX 数学公式，请按**数学含义**理解，
   不要把它当成普通文本或代码。
8. 若题干里出现 $?$、或消息里明说"信息不完整/被截断"，
   **不要作答**：输出 {"chosen_labels": [], "reason": "题面缺失：<缺什么>"}。
   空作答等于"停下来等人"，这不是失败，而是正确行为。
   —— 注意：视觉来源的题目**不给"最可能的一项"兜底**。
      猜错时从输出上看不出来，会被当成一次正常作答提交上去。
9. 数学题在给答案之前**自己验算一遍**（回代 / 唯一性 / 量纲 / 边界值），
   并在 reason 里用一句话写出验算要点。
   若验算发现解不唯一或与选项都不符，按第 8 条输出空作答。
```

**为什么第 8 条要和现有实现不同**：现有实现是「无法确定时，仍要给出你认为最可能的一项」。
这在 0.1.0 的 DOM 通道下是合理的（题面可信，只是模型没把握）；
但在**视觉通道**下，题面本身就可能是错的，而错误**不可见** ——
此时"给个最可能的"会把一次读题错误洗成一次正常作答。
**v0.2.0 起只存在后一种情形**（DOM 题目通道已删除），所以这一条不再是有条件的取舍，
而是**无条件规则**：题面不确定 → 空作答 → 停下来等人。
（下游还有硬约束 15「空作答绝不提交」兜住空作答这条路。）

**第 10 条（2026-09-30 加）：`confidence` 必须如实填。** 它服务的是「不开复算时的复核闸门」：
`sample_n == 1`（默认，不开复算）时，编排层**只看自报值** ——
低于 `guards.confidence_review_min`（默认 `0.5`）就标 `⚠复核` 并**停下等人**。
所以「题面完整但你自己没把握」一定要写低值：那正是需要人看一眼的那一类
（历史上踩到的形态是「安静的错答案」——看起来一切正常，只是答错了）。
开复算（`sample_n > 1`）时改用多数票占比，自报值不参与；
两种情况都**不许**因为「想让它继续跑」而虚报高值。

## 5. 编排层怎么串（伪代码）

```python
async def run(page):
    # ---------- 开局：读一屏，然后**裁决一次** ----------
    batch = await vision.read_screen(viewport_shot(page))   # 一份固定格式：page + questions
    plan  = derive_plan(batch)          # 推进方式 / 几何 / 提交范围 / 总题数 —— 只有这一次

    while True:
        for a in batch.questions:                     # 同屏多题一次拿走，不再逐题截图
            if a.qtype == "unknown" or a.clipped:
                return await reread_or_pause(a)       # 门禁：不下传
            for item in a.uncertain:                  # Pass B：只复核"可能决定答案"的项
                crop = magnify(viewport_shot(page), item.box, times=4)
                b = await vision.recheck(crop)
                if b.latex != item.latex:
                    c = await vision.recheck(crop, angle="换裁剪/换倍数")
                    if c.latex != b.latex:
                        return await pause_for_dump(item)     # 第三次仍冲突 → 停

            # ---------- 交接：只搬语义；标号=页面标号，顺序=页面顺序 ----------
            question = to_question(a)          # stem / qtype / options[].label+text
            geometry = to_geometry(a)          # 几何留在这里，不进 Question

            # ---------- 解题组（只吃文本）----------
            answer = await solver.solve(question)          # 不打乱；回 confidence

            # ---------- 执行层（只吃几何）----------
            for label in answer.chosen_labels:
                await actuator.click_by_box(geometry.option_box[label])

        # ---------- 推进：永远只用 plan 里那一种方式 ----------
        if not await advance_by(plan, page):   # CARD / CLICK / SCROLL / SWIPE，**不换招**
            break                              # 推不动 → 请视觉组确认是否全部完成 → 停或收工
        batch = await vision.read_screen(viewport_shot(page))
```

三个**必须保持的隔离**：

1. **执行层不许看解题组的输出文字**，只许看它给的**页面标号**；
2. **解题组不许看任何几何/图片**（`images` 恒为空；`Question` 里也没有坐标）；
3. **视觉组的 `uncertain` / `clipped` 不许被解题组"顺手抹平"** —— 它只进留痕与门禁。

第四件事**不是隔离，而是纪律**（2026-09-30 加）：**推进方式在开局定死，此后不换招**。
旧实现允许「点击找不到 → 改滚动 → 再改滑动」，真机上那条路的表现是
「一次滚动从第 3 题跳到第 16 题」，而且每一次换招都要再问一次模型「下一题在哪」——
同一次运行里出现两套判断逻辑，用户从日志上根本看不出它到底在按哪一套走。

| `solve/reader.py` | 只有一次读 | 加 Pass B 复核入口（裁剪 + 放大 + 结构化追问） |

> ⚠️ 与本次实测直接相关的两条**独立缺陷**（不属本契约范围，但同源）：
> ① `end_progress_patterns` 的 `共\s*(\d+)\s*[题頁页]` 会命中**小节标题**「共2题」，
> 而页面真实总题数是 5 → **可能被判成"最后一题"→ 静默跳题**；
> **已消除（P15）**：`perception/end_probe.py` 整套删除，改为「开局判定 + 收尾确认」。
> ② 5 题同页、只有题号导航没有「下一题」→ 旧的 `_advance` 三段（点击/滚动/滑动）全失败，只能做第 1 题。
> **已解决（2026-09-30）**：这种情况现在会裁决成 `CARD` —— 直接点答题卡上「下一题号」那一格，
> 落点由网格算术给出（`core/run_plan.py::card_cell_box`）。
> 三条相关纪律：①方式**开局定死**、此后不换招；②落点算不出来（超出卡片可见区域）就**不点**；
> ③推进后读到的题号与预期不符 → `advance_failed` 停下（防静默跳题）。

## 7. 2026-09-30 收口（这次改了什么、为什么）

用户对上一版的四条实测判词，以及对应改动：

| # | 判词（原话） | 改动 |
|---|---|---|
| 1 | 「下一题处理仍然存在严重问题，现在严格按照我的方法修改，程序开始运行时需要有一套判断逻辑，一旦判定好后后续的全部按照这套逻辑」 | 新增 `core/run_plan.py::derive_plan`：开局读图那一次就把①推进方式（恰好一种）②推进几何③提交范围④总题数定死，此后**全程照它执行**。阶梯换招、「滚到顶重读一次」、每题重问「下一题在哪」全部删除。推不动 → 请视觉组确认是否全部完成 → 确认才收工，否则 `advance_failed` 停下 |
| 2 | 「两套模型配合出现严重问题，视觉组模型的任务就是解读照片，将照片翻译成固定格式，解题组模型严禁拿到非文本输入」 | 视觉组输出收敛成**一份固定格式**（`page` + `questions`），且 `page` **只报告「有什么」**；解题组请求 `images` 恒为空（单测钉死），**取消选项打乱**、标号即页面标号。交接物就是那份格式本身 |
| 3 | 「置信度系统也存在bug，如果不使用复算系统则不存在置信度系统。目前不开启复算时存在模型无法解题的情况，处理这个bug」 | 解题组自报 `confidence`：不开复算用它（低于 `confidence_review_min` → `⚠复核` 停下），开了复算用多数票占比。**不可用的单次回复**改判为「请求失败」→ 有界重发（`SAMPLE_RETRY_MAX = 2`），不再当成一次无效采样 |
| 4 | 「动作 回读不一致判断逻辑存在问题，存在点击正确却判断错误导致胡乱操作」 | 回读改三态：`changed` / `weak` / `none`。点在有墨迹的行上却 `none` → 视为**已点中**（画面本来就没什么可变），**绝不换点**；只有几何兜底落点才换下一个候选；全部落点都 `none` 才停下等人 |

> 贯穿四条的一条纪律：**判断只做一次，之后按它执行**；做不了就**如实停下**，
> 不许换招、不许猜、不许静默跳过。这条纪律比任何单点修复都重要。
