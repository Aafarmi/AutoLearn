## 0. 一句话结论

**这类页面真正的难点不是解题，是「把题面准确拿到手」。**
题面里的数学公式全部是 **PNG 图片**、没有任何文字替身，
所以任何一个只看 `innerText` 的 AI（**0.1.0 里那条「DOM 读题通道」正是这么做的**）**必然读不到题** ——
而它又不会报错，只会安安静静地把 `设 ___ 为随机变量的概率密度` 当成完整题干交上去。

> 这一条就是 **v0.2.0 删掉 DOM 题目通道、只使用模型（视觉）** 的直接证据：
> 那条「最稳、零成本」的路在这类页面**永久不可用**，而「读错了却不报错」正是它最危险的地方。
> 现在读题只有一条路（截图 + 模型），代价是每题一次模型调用，
> 所以必须靠读题质量门禁（`clipped` / `uncertain` 非空就拦）把不确定性顶到人面前。

## 0.5 现在 AutoLearn 会怎么做（2026-09-30 收口，照这一节排障）

> §0 说的是「这类页面为什么难」；这一节说的是**程序当前的真实行为**。
> 与人工做题的差别：程序**只点选项**（填空/简答按设计拒绝），不导航、不关标签页、不猜答案。

### 0.5.1 开局会发生什么

1. **开局读一屏**（`core/orchestrator.py::_plan_run`）：截一张**视口图** → 视觉组按固定格式
   回一份 `{"page": {...}, "questions": [...]}`（`page` 是「这一屏长什么样」的观测）。
2. 程序拿这份**观测**裁决出**唯一一份方案**（`core/run_plan.py::derive_plan` → `core/models.py::RunPlan`），
   一次定死四件事：

   | 定死的东西 | 取值 | 怎么定 |
   |---|---|---|
   | 推进方式（**恰好一种**） | `card` 点答题卡题号 / `click` 点固定控件 / `scroll` 向下滚动 / `swipe` 滑动 | 按 `core/advance_library.PLAN_PREFERENCE = (card, click, scroll, swipe)` 顺序，第一个可行的胜出 |
   | 推进几何 | `control_box`，或答题卡的 `card_origin` / `card_step` / `card_anchor` | 答题卡网格开局算好，此后按题号**纯算术**推算；算不出来（返回 `None`）**绝不点** |
   | 提交范围 | 整卷 `paper` / 每题 `question` | 优先用观测说的；没有则「有答题卡 / 总题数 ≥2 / 一屏 ≥2 题」判整卷 |
   | 总题数 | 整数，或「不知道」 | 观测给的；不知道时**永远不算「做满了」** |

3. **方案会被记下来**：事件流里一条 `advance.calibrated`（界面「任务过程」显示成
   「开局判定：共 N 题，当前第 K 题，推进方式「…」（推进方式：…；总题数：…；提交范围：…）」）。
   payload = `method` / `total` / `current` / `scope` / `summary` / `reason`（外加 `run_id`）。
   开局这一屏读到的题**一道都不会白读**：首屏第 1 题直接作为第一道作答（日志 `vision_read: reused`），
   其余题留在队列里接着做（`queued`），整屏做完才推进 —— 所以开局那一屏**不会**再读第二次。
4. 之后**全程照这份方案走**：不再每题问模型「下一题在哪」、不再换成别的方式、
   不再「滚回顶部重读一次」、也不再因为「这一屏没有提交按钮」中途停下。推不动就停（§0.5.3）。

### 0.5.2 它会怎么翻到下一题

只走方案里那一种。日志里靠 `advance.calibrated` 的 `method` 认出选了哪一种：

| 方式（`method`） | 画面上长什么样 | 它具体做什么 | 怎么从日志看出来 |
|---|---|---|---|
| `card` 点答题卡题号 | 一屏一题，页面上有**题号网格**（1 2 3 … 44），往往**没有**「下一题」按钮 | 按题号算「第 N 格」的中心再点它；格子推算不出来就**不点**，直接进收尾确认 | `method=card`，`reason` 里带「N×M 格」；此后每条 `vision_read` 的题号应逐个 +1 |
| `click` 点固定控件 | 画面上有「下一题 / 下一页 / 继续」按钮 | 点方案里记下的那个框（`control_box`） | `method=click`，`reason` 里带控件文字 |
| `scroll` 向下滚动 | 一屏多题的长页面，下方还有内容 | 滚半步（视口高 ×`advance_scroll_step_ratio`=0.5）→ **再读一屏** → 确认新题进来了才算到位；有界（默认最多 `advance_scroll_max_steps`=12 步） | `method=scroll`；日志里 `advance=scroll` |
| `swipe` 滑动翻页 | 整屏一张卡、不可滚动 | 一次只滑一下（默认先左后上），证明这一下没生效才试下一个方向 | `method=swipe` |

推进之后会**校验题号**：读回来的题号与方案的预期不符 → 停下（`advance_failed`，
日志 `advance=wrong_question` 带 `expected` / `got`），避免「静默跳题」。

### 0.5.3 什么时候会停下等你

每一行都是「暂停理由 → 你该做什么」。暂停一定伴随**截图 + 留痕**，理由写在 `run.paused` 里。

| 暂停理由 | 什么情况 | 你该做什么 |
|---|---|---|
| `vision_read_failed` | 没有可用的视觉模型 / 截图失败 / 模型没回或回复解析不了 | 先去「模型库」选一套**支持图片**的模型并「测试连接」；再看 `logs/<run_id>/vision_read_raw.txt`（模型原始回复）与后台窗口日志 |
| `vision_read_empty` | 这一屏**一道完整题都没读到** | 核对画面：题目是不是被切了 / 还在加载；把它滚进视野后点「恢复」 |
| `vision_incomplete` | 读到了，但题面**残缺**（`clipped` 非空） | 核对那一屏：题干或选项有没有被裁掉/遮挡；调整窗口或滚动位置后「恢复」 |
| `vision_uncertain` | 读到了，但模型自己说**拿不准**（`uncertain` 非空） | 看 `vision_read.json` 里它标的框与文本，确认不是模型看错了画面 |
| `advance_failed` | 方案里那一种推进方式推不动，且视觉组**没能确认**「全部完成」 | ①手动点一次「下一题 / 题号」再「恢复」；②把推进控件/答题卡滚进视野后重跑；③确认它确实做完了 → 自己交卷 |
| `vision_no_submit_box` | **只在**收尾（整卷）或每题范围、且画面上确实看不到提交按钮 | 整卷：题目已全部作答，**请手动点一次「交卷 / 提交作业」**；每题：核对画面后重跑 |
| `submit_timeout` | 点过提交了，但截图差分没看到变化（按钮禁用 / 弹了确认框 / 要验证码） | 看截图确认卡在哪一步；手动处理确认框/验证码后「恢复」；**它不会自己重放提交** |
| `needs_confirm`（**必停复核**，事件 `solve.review_required`） | 复算一致率 < `guards.agreement_accept`，或单次自报 `confidence` < `guards.confidence_review_min`（默认 0.5），或模型**显式空作答**；半自动模式下每题也会停在这里 | 在题目的「需要你决定」里确认答案（事件 `solve.review_required` / `task.needs_confirm`，`reason` 会写 `review_flag` 或 `manual_mode`） |

### 0.5.4 怎么判断它有没有漏题

三道独立的关：

1. **推进后题号校验**：读回来的题号与方案预期不符 → 立刻 `advance_failed` 停下
   （日志 `advance=wrong_question`，带 `expected` / `got`）。
2. **收尾确认**：做满方案总数、或方案里那一种方式推不动时，都会请视觉组**再读一屏**，
   看 `page.completed` —— 只有 `all_done` 才收工；`not_done` / `unknown` / 问不成
   一律按**未确认**处理，停下等人（事件 `advance.completion_check`，带
   `completed` / `observed` / `progress` / `reason`）。
3. **留痕**（`logs/<run_id>/`）：

   | 看哪儿 | 能看到什么 |
   |---|---|
   | `events.jsonl`（run 级） | `advance.calibrated`（方案）、`vision_read=ok/reused/gated/failed/empty`（读了哪一屏、题号）、`advance=scroll/click/card`、`advance=wrong_question`、`advance.completion_check`、`submit=paper/skipped` |
   | `<item_id>/vision_read.json` | 模型给的每个框 + 那张图的尺寸（「坐标为什么是这个值」的直接出处） |
   | `<item_id>/solve.json` | 答案、`confidence`、`solve_path`、`review_flag`、采样明细 |
   | `<item_id>/action.json` | 点哪儿、`readback`（`weak_changed:…` / `no_change_on_ink:…`）、截图引用 |
   | `<item_id>/verify.json` | 截图差分结论（`region_mad` 与三态 `changed`/`weak`/`none`） |

   把 `events.jsonl` 里的题号序列拉出来（1 → 2 → 3 …）就能看出有没有跳号。

### 0.5.5 交卷

- **整卷范围（`paper`）**：只有「视觉组确认全部完成」之后才自动点一次交卷
  （`_completion_confirmed` 是主闸门），而且**绝不重放**。
- 交卷按钮的框有**三个来源**（按范围排序）：开局方案里的 `submit_box`；**最近一次读图**
  看到的框（每题范围优先用它 —— 当前这道题所在那一屏的按钮才作数）；
  收尾那一屏读到的框（整卷范围优先用它 —— 「交卷」常常只在收尾那屏才露出来）。
  每一对**框与尺寸都同源**（拿 A 屏的框配 B 屏的尺寸就是「点歪了」）。
- 三个都没有 → 提示「**请手动点一次交卷**」并暂停（不是卡住，是缺最后一下人工动作）。
- **每题范围（`question`）**：每题提交一次；找不到按钮必须停下（答案可能没被记录）。
- 提交失败/超时：只暂停，**不重试、不重放**。
- 整卷交卷**确认生效之后**，这一轮已作答的题会**一起**被标成终态（`verified`）——
  否则它们停在 `applied`（不是终态），续跑时会被**重做一遍**，多选题上重新点选项
  就是把刚选上的勾**取消**。提交失败/停下的那一卷**不**这样标（结果未知，保持原状）。

### 0.5.6 2026-09-30 收口（四条修复 + 为什么）

1. **开局判定一次，之后全程照它走**（`core/run_plan.py::derive_plan` → `RunPlan`）：
   推进方式（恰好一种）、推进几何、提交范围、总题数在开局定死。随之删掉的是运行期的
   「点击 → 滚动 → 滑动」降级、「滚回顶部重读一次」、「这一屏没有提交按钮就中途暂停」、
   「每题问一次模型下一题在哪」。**为什么**：每一步临时判断 = 一次可能跳过十几道题，
   而跳题的代价不对称（漏掉的题几乎没人会发现）。
2. **视觉组只做观测、解题组只吃文本**：所有读图请求返回**同一份固定格式**
   （`page` 观测块 + `questions`）；解题组请求里 `images` 恒为空；选项顺序与标号
   **一律照页面原样**（不重排、标号可能不连续如 A、B、D）。**为什么**：把「该怎么推进」
   交给看不见程序的模型，它每次的说法都可能不一样；标号一旦错位，下游**从输出上看不出来**。
3. **置信度两种口径 + 有界重发**：不复算用模型自报 `confidence`（低于
   `guards.confidence_review_min`=0.5 → 标 `⚠复核` 停下），复算用多数票占比；
   「回复不可用」走**有界重发**（`solve/solver.py::SAMPLE_RETRY_MAX`=2，每条采样项最多 3 次请求），
   「显式空作答」是**模型的结论**、不重发。**为什么**：单样本的一致率恒为 1.0、不带任何信息；
   把「这一次回复坏了」与「模型说没有答案」混成一件事，故障只在不复算时暴露。
4. **回读三态 + 墨迹上「没变化」不重点**：`changed`（≥2.0）/ `weak`（≥0.05）/ `none`；
   落在选项自己文字上（`ink_centroid`）点完 `none` → 按「本来就已选中」收工、**绝不重点**；
   几何兜底落点 `none` 才换下一个候选点。**为什么**：画面本来就没什么可变时
   （选中态很轻、纯图片选项），旧判据会判「没点中」→ 反复换点、乱点一气，
   多选题上还会把刚选上的勾取消。

## 2. 铁律（违反必出事）

1. **先只读。** 读完题、解完题、用户点头之前，**不点任何东西、不打一个字**。
2. **`innerText` 不是题面。** 有公式的题必须把每张公式图还原出来，否则题干是残缺的，而且**残缺得毫无提示**。
3. **公式图必须走浏览器会话取。** 裸 `httpx/requests` 会被 CDN 拒（本页实测 403）。
4. **公式图必须先合成白底。** 字形在 alpha 里，RGB 全黑 —— 不做 alpha 合成只会得到一张全黑图。
5. **不确定的字形绝不猜。** 走 §3 的三级证据链：双读互证 → 裁剪放大 → ASCII 像素直读。
6. **拿数学当校验和。** 如果某个读法让答案变得「唯一且干净」，它极大概率是对的；如果让答案变得很丑（$a=\ln 8$、$7/8$），先怀疑读错了。
7. **提交是整卷动作、不可逆。** 未经用户明确要求，**绝不点「提交」**；**也不擅自点「保存」**（保存有服务端副作用）。
8. **写回必须回读验证。** 写之前先确认那一格是空的；写完逐项读回来核对。
9. **填空/简答用真实键盘输入**到 contenteditable，**不要**改 `innerHTML` —— 页面的 `contentChange` 监听、答案收集、字数统计都挂在真实输入上。
10. **不导航、不关标签页、不碰用户其他页面。**

## 3. 核心技巧：三级证据链（本次最值钱的部分）

### 第 1 级 —— 让模型**同时**给出 LaTeX 与中文读法，互相印证

关键不是「让它转写」，是**让它用两种互不相同的表示说同一件事**。
两者不一致就说明它没看清。

```json
{
  "latex": "用最简 LaTeX 转写这个表达式",
  "desc":  "用一句中文把这个式子读出来，例如「闭区间，从负二分之π到0」"
}
```

并在提示词里明确禁止它用 `bmatrix/matrix/cases` 去凑区间 ——
本页第一遍四个选项全被凑成了 `\begin{bmatrix}...\end{bmatrix}`，**四个全不可信**。

> 一致性检查：`latex` 说 `[-\frac{\pi}{2}, 0]`、`desc` 说「闭区间，从负二分之π到0」→ 两条独立路径同结论，可信度大幅提升。

### 第 2 级 —— 裁剪可疑区域 + LANCZOS 放大 3~5 倍，再问**结构化问题**

不要问「这是什么」，要问**可判定的分量**：

```json
{
  "latex": "...",
  "exponent_of_x": "字母 x 的指数（只写数字，没有写 1，看不清写 null）",
  "root_index": "几次方根（只写数字，没有写 null）",
  "letters": ["画面里出现的英文字母，从左到右，区分大小写"],
  "desc": "..."
}
```

放大用 **LANCZOS**；太小读不出，太大（×8）反而糊成团块。

### 第 3 级（决定性）—— 把图渲染成 ASCII，**自己读**

这一级能解决模型绝对解决不了的问题：**一个横杠到底是负号还是等号**。

做法（三步都不能少）：

1. `alpha_composite` 到白底 → `convert("L")`
2. 取 ink 包围盒，按阈值（约 `<170` 为墨）逐像素打印 `#`
3. 需要时 LANCZOS ×2 再打印

#### 实战判读规则

| 要分辨 | 判据 |
|---|---|
| `=` 还是 `−` | **两根横杠分居数学轴线两侧 = `=`**；**一根横杠正压在轴线上 = `−`** |
| 上标是 `3` 还是 `2` | `3` = 顶杠 → 右侧笔画 → **中杠** → 右侧笔画 → 底杠（五段）；`2` = 顶杠 → 右侧 → **斜向左下** → 底杠（**没有中杠，也没有第二段右侧笔画**） |
| 大括号 `{`（cases）还是圆括号 `(` | 大括号在**中间高度有一处向外的凸起**；圆括号是平滑弧 |
| 分数结构 | 找到**最宽的那根横杠**；其上为分子、其下为分母；`π` 是「顶杠+两条腿」，`2` 是「弧+斜+底杠」 |

本次靠这一级确认了三件**决定答案**的事：

- 第 2 题题干 `f(x)` `=` `−` `sin` `x` —— **负号确实存在**（否则答案从 A 变 B）
- 第 2 题四个选项 = `[−π/2,0]`、`[0,π/2]`、`[−π/2,π/2]`、`[−π/2,3π/2]`
- 第 4 题上标 = **3**（`X³`，不是 `X²`）
- 第 5 题分母 = `a·∛(x²)`、条件 = `1 < x < 8`

### 第 4 级 —— 数学自检（最便宜的守门员）

- **唯一性**：第 2 题四个区间里只有一个同时满足「$f\ge0$」与「$\int f=1$」，且它的积分**正好等于 1** → 反证区间读对了。
- **干净性**：第 5 题 $\int_1^8 x^{-2/3}dx=3\Rightarrow a=3$。若读成 $x^{-2}$ 会得到 $a=7/8$、读成 $\sqrt{x^2}$ 会得到 $a=\ln 8$ —— **丑答案就是读错了的信号**。
- **回代**：算出 $p=1/3$ 后代回 $1-(1-p)^2=5/9$ ✓；算出 $f_Y$ 后积一遍 $=1$ ✓。

**C. ASCII 自读（不是给模型的，是给你自己看的代码配方）**

```python
# 1) 取图：必须走浏览器会话，裸 HTTP 客户端会被 CDN 拒
resp = await page.request.get(url); blob = await resp.body()

# 2) 合成白底：字形在 alpha 里，RGB 全黑 —— 少了这步就是一张全黑图
im = Image.open(BytesIO(blob))
rgba = im.convert("RGBA")
bg = Image.new("RGBA", rgba.size, (255, 255, 255, 255))
flat = Image.alpha_composite(bg, rgba).convert("L")

# 3) 可选放大：读的时候用 LANCZOS ×2；×8 会糊成团块
if scale > 1: flat = flat.resize((flat.width * scale, flat.height * scale), Image.LANCZOS)

# 4) 裁到 ink 包围盒，逐像素打印
px = flat.load()
ink = [(x, y) for y in range(flat.height) for x in range(flat.width) if px[x, y] < 170]
x0 = min(p[0] for p in ink); x1 = max(p[0] for p in ink)
y0 = min(p[1] for p in ink); y1 = max(p[1] for p in ink)
for y in range(y0, y1 + 1):
    print("".join("#" if px[x, y] < 170 else ("+" if px[x, y] < 230 else " ")
                  for x in range(x0, x1 + 1)))
```
