# 推进技能：点答题卡题号进下一题（`advance_card`）

## 适用范围

只用于「画面上有**题号答题卡**（一片由题号数字组成的网格）」的页面。真实作业页（一屏一题、44 题）最常见就是这种：**没有**「下一题」按钮，切题只能点网格里的题号。

## 什么时候选它

- 画面里能看到一片**题号数字**（1、2、3 …）组成的网格，通常贴在左侧或右侧；
- 当前题号与**下一题号**的格子都看得见（或至少能由网格推算出来）；
- 它与 `advance_click` 同时存在时**优先选它**：点「下一题号」那一格是最直接的落点，不依赖控件会不会移位。

> **答题卡 ≠ 选项列表。** 答题卡里每格只有一个**题号数字**，点它只会跳到那道题，不会作答。
> 把选项列表当成答题卡，会让执行层一按就跳到别的题 —— 这是本技能最严重的误判。

## 要给出的观测

| 字段 | 内容 |
|---|---|
| `advance_skill_id` | 固定写 `"advance_card"` |
| `page.card.box` | 答题卡**整体可见区域**的框（含所有题号格，不含标题与留白） |
| `page.card.cols` / `rows` | 题号排成几列几行（看得见的部分） |
| `page.card.current_box` | **当前题号**那一格（校准整片网格的锚点，尽量给准） |
| `page.card.next_box` | **下一个题号**那一格（当前题号右边 / 下面那格），最直接的落点 |

所有框都是**本屏**量出来的归一化坐标。开局算好的答题卡几何会漂移（页面宽度变化、答题卡展开/收起、滚动条出现），所以**每一步都要重给一次** `card`：`next_box` 就是这一步的落点。

## 判定步骤

1. 在**本屏**确认网格的题号范围与当前题号，读出 `cols` / `rows`。
2. 量出整片网格的 `box`，以及当前题号格 `current_box`；能看见下一题号格就一并给 `next_box`。
3. 给 `advance_skill_id: "advance_card"`。
4. 下一屏**重新量一次**：目标题号变了（不是简单的 +1 时尤其如此），`current_box` 与 `next_box` 也会变。

## 禁止事项

- 不沿用上一屏的 `card`：几何漂移正是「点了 27 号格却读回 26 题」的成因之一。
- 不把选项列表、题干里的编号列表当成答题卡。
- 网格推不出来（缺 `cols` / `rows`、下一题号格不在可见区域）时**不要硬给**：老实报告你看到的范围，程序会停下而不是点一个算出来的空位置。
- 不给答案、不改题型、不写散文式解释。

## 简短示例

```json
{
  "page": {
    "current": 26,
    "advance_skill_id": "advance_card",
    "card": {
      "box": [0.012, 0.10, 0.155, 0.60],
      "cols": 5,
      "rows": 9,
      "current_box": [0.012, 0.31, 0.028, 0.05],
      "next_box": [0.042, 0.31, 0.028, 0.05]
    }
  },
  "questions": []
}
```

示例里的坐标只属于那一屏；下一步必须重新量，不能把 `next_box` 往下挪一格当作新落点。
