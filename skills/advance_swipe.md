# 推进技能：滑动进下一题（`advance_swipe`）

## 适用范围

只用于「**题目在同一屏里排成一行 / 一列**，没有可点的推进控件，只能把它滑走」的页面。典型形态：整屏一张长页纸，下面接着下一题；或横向卡片流，一张卡一道题。没有可用控件、页面又不能滚动时也只能走它。

## 什么时候选它

- 画面里**看不到**「下一题」控件，也**没有**题号答题卡；
- 但能看出题目是**同屏连续排列**的：当前题的下方/右侧就是下一题（而不是「滚不动的一整屏」）；
- 此时给出 `advance_skill_id: "advance_swipe"`，**并且必须**给出幅度依据。

## 要给出的观测

| 字段 | 内容 |
|---|---|
| `advance_skill_id` | 固定写 `"advance_swipe"` |
| `page.swipe.direction` | `"up"`（向下滚动看下一题）或 `"left"`（横向卡片流往左翻）。**只认这两个** |
| `page.swipe.amplitude` | 相对**视口宽 / 高**的移动比例：`> 0` 且 `<= 1`（例如 `0.6`） |
| `page.swipe.reason` | 一句话依据（只进留痕）：你按什么估的这个幅度 |

**幅度怎么估**（这是本节唯一需要「判断」的地方，仍然只报事实）：

1. 看**当前这道题在屏上占多高**（或横向卡片占多宽）——下一题要顶上来的距离大致就是它；
2. 宁可**略小**再走一步：小幅滑动后重读一屏，题号对得上就继续；滑过头则是**静默跳题**，
   事后只能从题号跳变里发现（真机事故：题号从 3 直接跳到 16）；
3. 一整屏就是一道题、下一题紧接着时，给接近 `1`（例如 `0.9`）而不是 `1.0`；
   题目只占小半屏时给 `0.3`~`0.5`；
4. 说不清依据时**不要**给一个「差不多」的数 —— 省略 `advance_skill_id`，让程序按开局裁决推进或停下来问人。

## 判定步骤

1. 确认真的没有可点的推进控件、也没有题号答题卡（有的话优先 `advance_click` / `advance_card`）。
2. 判断方向是纵向往下看下一题（`up`）还是横向往左翻（`left`）。
3. 按「当前题占屏比例」估幅度，写进 `amplitude`。
4. 点/滑完之后的下一屏**重新判断一次**：题目可能已经换了一批，幅度依据也随之改变 —— 沿用上一屏的幅度是跳题的常见起点。

## 禁止事项

- **不猜幅度**：`amplitude` 是执行层唯一的滑动手势依据，猜一个就是一次真实可能滑过头的手势。
- 不用 `right`（往回翻）、不用含糊说法（`next`、`forward`、`scroll`）：认不出方向时整块丢弃。
- 不写「向下滚动一整屏」这类散文代替数字；依据放 `reason`，数字放 `amplitude`。
- 不给 `advance_swipe` 之外的方向值；不加 `duration` / `distance` 等未定义字段。
- 不改题型、不给答案。

## 简短示例

```json
{
  "page": {
    "current": 12,
    "advance_skill_id": "advance_swipe",
    "swipe": {
      "direction": "up",
      "amplitude": 0.62,
      "reason": "当前题占屏高约六成，下一题紧接在下方，滑六成刚好把它带到屏顶"
    },
    "scrolling": true
  },
  "questions": []
}
```

示例只对那一屏成立；换屏之后方向与幅度都要重估。
