> 2026-09-28 20:21 的一次真实运行。用户问「这又是为什么」。
> **结论先说**：真因**没能 100% 确定**，因为这次失败**没有留下任何证据**。
> 我把三条可能的路径都堵上了，**并补上了留痕** —— 下次再出，一眼可定。

## 一、这次运行发生了什么

```
20:21:22  task.created            发现新任务
20:21:26  advance.calibrated      开局标定：共 44 题，推进方式「向下滚动」
20:21:26  perception.done         读到内容（通道 vision）—— 这一步只是「截了图」
20:21:34  log.line                ��← 这里本该有内容，但界面上是空白的
20:21:34  run.paused（perception_failed）
20:21:34  run.finished
```

数据库里：`run.status = paused:perception_failed`，而 `task_item` **一行都没有**；
`logs/` 目录**是空的**。也就是说 —— **一道题都没认领**：模型读图这一步就没过。

## 二、查出来三件事（没有一件是"再试一次就好"）

### 1. 界面把唯一的线索吞掉了 ← **这是你看到「log.line 空白」的原因**

前端 `app.js::appendLog` 对 `log.line` 事件**只取 `payload.line`**：

```javascript
if (eventName === "log.line") text = (payload && payload.line) || "";
```

而编排层发的都是**结构化诊断**：

```json
{"vision_read": "failed", "error": "read_parse_failed", "hint": "…"}
```

→ `payload.line` 不存在 → **text 为空** → 界面上只剩一个孤零零的事件名。
**读题失败时唯一的线索，就这样被前端丢掉了。**

### 2. 一屏多题的输出**很可能被截断**

上一轮我把提示词改成「一次抄整屏的题」，但**没动 token 预算**：

```python
READ_MAX_TOKENS = 2048   # 读题用的 token 预算
```

一屏 3~4 道题的完整 JSON（题干 + 选项 + 坐标 + 公式）很容易超过 2048。
而**被截断的 JSON 用 `json.loads` 是整份失败的** ——
明明前面几道抄得好好的，却**一道都读不到**，界面只说一句 `perception_failed`。

### 3. 预检**没有检查「模型能不能看图」**

`ui/runner.py::preflight` 只查「有没有模型配置」：

```python
if not registry.active_chain():
    raise TaskStartError(ErrorCode.NO_CONFIG, "还没有可用的模型配置…")
```

**没查那套配置支不支持视觉。** 而读题就是**发图**给模型 ——
纯文本模型收不了图，跑起来必然卡在读题。

更能说明问题的是：`ui/guide.py` 里那张 `GUIDE_VISION_UNSUPPORTED` 引导卡
（标题「当前模型不支持图片输入」，还写了三条出路）**早就写好了，却没有任何调用方** ——
这是一个**漏接的检查**。

## 三、修了四处

| # | 修什么 | 落在哪 |
|---|---|---|
| 1 | **结构化诊断在界面上可见** | `app.js::appendLog`：`log.line` 没有 `line` 字段时回退到 `JSON.stringify(payload)` |
| 2 | **截断不再等于"全丢"** | `solve/reader.py`：`READ_MAX_TOKENS` 2048 → **4096**；新增 `_scan_question_objects()` 逐个对象抢救（完整几道就交几道）；同时**接受裸数组**（模型把"一屏多题"理解成"给我个列表"太自然了）；提示词加「**最多抄 5 道**」 |
| 3 | **启动前拦住不支持视觉的模型** | `ui/runner.py::_vision_capable()` + preflight 抛 `VISION_UNSUPPORTED` —— 把那张沉睡的引导卡接上。判据只拦「**明确知道**都不支持」；`capabilities is None`（还没测过）**算放行**，否则会把刚装好还没点过「测试连接」的用户拦在门外 |
| 4 | **失败必须留下证据** | 解析不出来时 `logger.warning` 打印**模型原始回复前 400 字**（后台窗口可见）；暂停理由从兜底的 `perception_failed` 改成具体的 `vision_read_failed` |

## 四、诚实交代：真因没定下来

**为什么定不下来**：这次失败**没有留下原始回复**。

- 读题失败的回复**不落盘**（当时只在解析失败时静默跳过）；
- 失败路径也**没有 item**，所以连 `logs/<run_id>/<item_id>/` 目录都不会建。

对比上一轮（P17）我能一路定到「点的是行尾空白」—— 靠的正是项目那条
**「失败一律暂停 + 截图 + 留档」**的纪律。而**读题这条路当时没被那条纪律覆盖**。

所以我做的第一件事不是猜，而是**把观测补上**：

> **没有证据时，先补观测，再补防御。**
