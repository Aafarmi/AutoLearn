# AutoLearn 实施规划书 — 任务概览

## 做了什么

读取了项目资产中的《AutoLearn-项目任务书》v1.0（T0 定义冻结 + M0–M6 里程碑 + 场景 A 网课自动化 / 场景 B 刷题自动化），把它从「WBS 任务清单」拆成了**可直接开工的施工图**：

- 8 个里程碑 → **10 个可认领工作包（P0–P9）**
- 每个 Part 钉死：功能边界 / 交付文件 / 接口签名 / 验收口径 / 依赖 / 易踩的坑
- 冻结了 **Python 接口契约**（6 个模块族约 60 个签名）+ **REST API 契约表**（19 个端点）+ SSE 事件清单 + 6 张 SQLite 表
- 制定了 **6 类命名规范**（文件 / 标识符 / 事件 / REST / 前端 / 新增文件落位）
- 给出 **4 条并行泳道**与 8 个波次排期，标出关键路径与唯一强制止损点

## 关键决策

| 决策 | 理由 |
|------|------|
| 按「能否并行」而非里程碑切 Part | 里程碑是验收单位，Part 是认领单位；混用会让人等依赖 |
| P5 UI 从 W1 就独立开工 | 它是唯一全程独立车道，且 M2 闸门判定卡在 UI 可用性上 |
| P0 契约冻结不可压缩（半天） | 8 项定义未冻结就动手，会在 M3/M4 冒出错答与重复提交类缺陷 |
| 后端路由拆分（`ui/routes/*`），前端保持零构建单页 | 后端并行开发不互相踩，前端仍满足任务书「零构建」要求 |
| 新增媒体锚点文件 `selectors_media.yaml` | 任务书只列了 `selectors.yaml`，但课程页锚点语义不同，分离可避免 M5 回头改抽象 |
| 补 `core/trace.py` / `core/ratelimit.py` / `core/events.py` | 留痕、限速、SSE 事件原任务书分散在各里程碑，集中落 core 便于 P5/P7 并行 |
| 锚点抽象一次定完，P2 之后不再改 | 这是任务书明确的返工风险点（M5 回头改抽象） |
