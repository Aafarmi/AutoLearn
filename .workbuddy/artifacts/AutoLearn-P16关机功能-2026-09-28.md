# P16 · 一键关机（关闭全部相关端口）

> 交付时间：2026-09-28 · 需求：「关闭靶场，同时为程序添加一个关机按钮，可以便捷的关闭所有相关端口」

## 它解决什么

程序有三种运行形态，各自留着一批端口，而且**关掉一个不等于关掉全部**：

| 形态 | 进程结构 | 以前要怎么做 |
|---|---|---|
| `run.bat`（最常用） | **两个独立进程**：靶场 8899/8900 一个窗口、UI 8800 一个窗口 | 手动关两个黑窗口 |
| `launcher.py`（打包桌面版） | 单进程：三服务 + pywebview 窗口 | 关窗口即可 |
| 裸 `uvicorn` | 只有 UI 8800 | Ctrl+C |

还有一类**从来没人管**的：`POST /api/targets/launch`「接管启动」起的浏览器 ——
它带着 `--remote-debugging-port`（默认 9222）、是**独立进程**，父进程退出带不走它。
改造前它甚至没有任何长期持有者（`make_browser_source()` 每次调用都新建实例，
请求一结束对象就被回收），所以「程序关了、那个浏览器还占着调试端口」。

**现在**：顶栏右侧「⏻ 关机」一次收掉全部。

## 怎么用

1. 控制台右上角点 **「⏻ 关机」**；
2. 弹出清单（内容来自后端 `GET /api/system/status`，与判定同源）：
   ```
   · 停止控制台服务（127.0.0.1:8800）
   · 停止本程序另起的靶场进程（端口 8899 / 8900）
   · 关闭本程序「接管启动」的浏览器（N 个进程）—— 你自己打开的浏览器不会被关闭
   · 正在运行的任务会被中断（想留着就先「暂停 / 停止」）
   ```
3. 点「确认关闭」→ 出现「已关闭」提示，控制台页面断开、端口全部释放。
4. 有任务在跑时会先**拦一次**（409），要你明确再点一次「仍然关闭」。

命令行等价物：
```bash
curl -X POST "http://127.0.0.1:8800/api/system/shutdown"            # 有任务在跑会被拦
curl -X POST "http://127.0.0.1:8800/api/system/shutdown?force=true"  # 中断任务也要关
curl "http://127.0.0.1:8800/api/system/status"                       # 只看会关什么（只读）
```

## 三条设计决策

1. **只关自己起的** —— 端口归属分 `self` / `sibling` / `foreign` 三态，必须同时满足
   ① 端口在名单（8800/8899/8900）② PID 不是自己 ③ 可执行文件与本进程解释器一致，
   才动手；否则归 `foreign`，**只写进报告不碰**。按端口盲杀会误伤别人的服务。
2. **先回执、后动手** —— 收尾挂在 `BackgroundTasks` 上，响应先发出去（否则前端
   看不到任何反馈），`apply_shutdown` 自带 0.35s 宽限 + 4s 兜底硬退。
3. **前端用探活判成败** —— 响应常常被进程退出截断（`fetch` 直接 reject），
   这时关机其实**成功了**。前端先显示「正在关闭」，再用 `/api/health` 探活确认，
   避免把成功报成失败。

## 施工中抓到的真 bug

**虚拟环境下 `sys.executable` ≠ 进程镜像路径。**

第一轮冒烟里，靶场进程（PID 49672）被判成了 `foreign`：

```
{"port":8899,"pid":49672,"owner":"foreign",
 "exe":"…\\binaries\\python\\versions\\3.13.12\\python.exe"}   ← 基础解释器
```

而 UI 进程的 `sys.executable` 是 `…\AutoLearn\.venv\Scripts\python.exe`。
两者指向同一个解释器镜像的两种写法 —— 于是 `run.bat` 起的靶场被判成「外人」，
清单老实写着「端口 8899/8900 被别的程序占着，不会动它」，**一个都没释放**。
本项目**永远**跑在 `.venv` 里，等于这条判定从来没生效过。

修法：`own_executables()` 返回 `sys.executable` + `sys._base_executable` **一组**候选。

> 这类坑**纯单测发现不了**（单测里 exe 查询是我注入的假函数），
> 只有真起两个进程才暴露 —— 这就是端到端冒烟不可省的理由。

另修：前端把占位 `li` 与真清单混在同一元素里，自检在「请求还没回来」的瞬间
把占位读成了清单（只 1 条、不含端口）。拆成两个元素后解决。

## 注意

- **你自己打开的浏览器永远不会被关** —— 只有本程序「接管启动」的那个（我们在
  `launch()` 里亲手起的）才在名单里。
- 端口若被**别的程序**占着，不会被碰，只在清单里如实说明。
- `scripts/check_ui.py` **不点「确认关闭」**：自检与 uvicorn 同进程，点了会把自检自己关掉。
  收尾路径由 `tests/test_system_shutdown.py` 覆盖（可注入假 exit / 假 kill）。
- `launcher.py`（桌面版）**不需要改**：单进程形态下 `os._exit` 会连窗口一起收掉，
  清单里那两条端口会显示为「随本进程一起退出」。
