# P17 · 修一个「点不中」的 bug + 一屏多题识别

> 2026-09-28 · 触发：用户实测报告 `readback_mismatch` ×4 → `action_failed`，
> 并附上运行日志与页面截图。同时提出两项改进与一个问题。

## 一、故障与根因（先看证据）

日志最后几行：

```
18:03:39 act.readback_mismatch  ×4（18:03:39 / 41 / 42 / 44）
18:03:44 act.level_used 动作降级到 ?
18:03:44 task.state_changed 已应用 → 失败
18:03:44 run.paused 已暂停（action_failed）
```

项目「失败必截图留档」，所以留痕目录里有全部证据（`logs/a090315220c6/…`）：

| 证据 | 内容 |
|---|---|
| `action.json` | `"error": "action_ladder_exhausted: readback_mismatch: region_mad=0.00"` |
| `before.png` / `error.png` | 958×944，**逐像素比对后差异只有右上角计时器**（885,17)-(932,34) |

**两条推理**：

1. `region_mad = 0.00` 是**完全为零**，不是"差一点"；
2. 如果第一次点击选中了 A，A 的圆圈会变蓝 → 差异区域必然包含它 —— 但差异里**只有计时器**。

→ **结论：4 次点击全部落在没有选项的地方，选项从未被选中。**

再量 `before.png` 的几何：A 选项文字只占 **x=182~349**，而那一行延伸到 **x≈918**。
所以只要模型把框给到"整行"，框的**几何中心**（≈531）就落在**文字右边一大片空白**里 ——
而执行层当时点的正是几何中心。

**根因不是"点得不够准"，是"点的地方根本不是选项"。**

为什么会框到整行？因为视觉组提示词当时写着：

> `box` 要框住该元素**可点击的整行区域**（含标号），不是只框文字。

这条措辞在真实站点上把人带沟里了 —— 页面并不会让整行都可点。

## 二、修了什么

### 1. 执行层：点**框内内容质心**，不再点几何中心（核心修复）

`act/screen.py` 新增 `region_ink_centroid()` / `candidate_points()`：

- **首选落点 = 框内暗像素的加权质心**（抗锯齿淡边算轻权、笔芯算重权）→
  点的是"字最密的地方"，**框给多大都不怕**；
- 拿不到内容（纯色块 / 图片选项 / 框本身就框错了）→ 回退几何中心；
- 候选点按 `内容质心 → 几何中心 → 左半中心 → 偏上中心` 排好。

`act/actuator.py`：`select_option` 重试时**逐次换候选点**，不再重复同一个坐标 ——
「没生效」有两种相反成因：*点对了但还没渲染*（重放同点）与 *点错位置了*（必须换点），
旧实现只会做前者，所以 4 次全打在同一个空白处。
`click` / `submit` 也走同一套取点（代价是多一张截图，换"点得中"）。

**实测验证**（用真实的 `before.png`）：

| 模型给的框 | 旧行为（几何中心） | 新行为（内容质心） |
|---|---|---|
| 整行宽 | (531, 239) → **行尾空白** ❌ | (270, 231) → **选项文字上** ✅ |
| 整行宽 + 含行距 | (529, 242) → 空白 ❌ | (276, 235) → 文字上 ✅ |

(531,239) 正是日志里那 4 次点击的落点。

### 2. 视觉组提示词：box 收紧 + **一屏多题**

`prompts/10-视觉组.md`：

- **删掉"框住整行区域"**，改为「紧贴标号+文字的**外接矩形**」，并写明**为什么**
  （框拉大 → 中心落到空白 → 那一下等于没点）；
- 输出契约由**单个对象**改为 **`questions` 数组**：把这一屏里**所有完整题目**都抄出来，
  被切掉半截的题**不进数组**；
- **不再要求模型输出 `qid`**（下游按题干自己算，让它算只是白占篇幅还容易错）。

### 3. 「减少消耗」怎么落的：编排层复用同屏题目

`core/orchestrator.py`：

- 读一次图 → 一屏里的题**全部**入册（几何一并记好），第一道作为当前题，其余进
  `_pending_reads` 队列；
- 主循环取题**先查队列** → **不截图、不调模型**；
- `_advance()` **入口清空队列**（推进必然改画面，旧几何就作废了），
  `_reread_at_top()` 滚动之后同样清空。

长页面一屏 2~3 题时，从前**每题各付一次截图 + 一次模型调用**，现在一屏一次。
`vision_read=ok` 事件里带 `batch` / `queued` 两个数，省了多少一眼可见。

### 4. 顺带补上的观测缺口

- 读题的**原始回复**（`ReadBatch.raw`）现在会留在失败日志里 ——
  这次事故最关键的证据（模型到底给了多大的框）**当时根本没落盘**，只能靠截图反推；
- `scripts/check_read.py` 升级为读**全部题目**，并同时打印**模型给的框**与
  **程序会点的那一点**（`→ 点(x,y) [ink_centroid]`）—— 以后一眼就能看出会不会点空。

⚠️ 这些文件是**导入时读一次**：改完**必须重启服务**（`prompts/` 已计入 `code_rev()`，
`scripts/check_server.py` 能判出"改了没生效"）。

## 四、两个提示词的改动（结合本次测试结果）

**`10-视觉组.md`** —— 见 §二·2。核心是**坐标怎么给**：这是唯一能决定"点不点得中"的输入。

**`20-解题组.md`** —— 新增一节 **「作答与落到页面上」**，把你说的"操作也属于解题组"
这条放进去：`chosen_labels` **不是评测答案而是一张操作指令** ——
程序会照它用视觉组给的坐标**真点一下**，所以「答对」有两层：

1. 算对（既有纪律）；
2. **能落下去** —— 标号必须是**页面上那一个选项的标号**，不能按"我觉得的顺序"重排；
   多选题给完整集合（程序会**逐个**去点）；
   拿不准就空作答（空作答停下等人；猜一个会被**真的点到用户页面上**，且从输出上看不出来）。

> 一句话写进了文件：**你这一环没有"草稿"**。
