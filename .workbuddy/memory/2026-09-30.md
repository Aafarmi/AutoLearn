### ① 开局判定一次，之后全按它走

- 新增 `core/run_plan.py`：`derive_plan(batch, *, batch_size=0) -> RunPlan`
  （`RunPlan` 在 `core/models.py`，**取代** `TaskCalibration` / `AdvanceLook`）。
  开局读图那一次定死四件事：推进方式（`CARD`/`CLICK`/`SCROLL`/`SWIPE`，**恰好一种**）、
  推进几何（`control_box` 或答题卡 `card_origin`/`card_step`/`card_anchor`）、
  提交范围（`PAPER`/`QUESTION`）、总题数。
- 优先级 `core/advance_library.PLAN_PREFERENCE = (CARD, CLICK, SCROLL, SWIPE)`
  （`DEFAULT_METHOD_ORDER` 保留为别名，语义**不再是「阶梯」**）。
- **删除**：换招阶梯（点击→滚动→滑动）、「滚到顶部重读一次」（`_reread_at_top`）、
  每题重问「下一题在哪」（`find_advance_control`）、因为「这一屏没有提交按钮」中途暂停。
- 推不动 → `_settle_end` → 请视觉组确认「是不是全部完成了」→ 确认才干净收工，
  否则 `advance_failed` 停下等人。推进后题号与方案预期不符 → 同样停下（防静默跳题）。
- 答题卡落点是**纯算术**：`grid_geometry` + `card_cell_box`，网格按行换行
  （`divmod(index, cols)`，第一版 `origin + index*step` 会把第 17 格算到卡片外）、
  容差 `CARD_GRID_TOLERANCE = 0.10`；算不出来返回 `None` → **绝不点**。

### ③ 置信度：不开复算时用模型自报值

- 解题组输出新增**必填** `confidence`；`solve/prompts.py::parse_confidence` 认
  `0.8` / `"0.8"` / `"80%"`，越界**夹到** `[0,1]`（bool/NaN → `None`）。
- 不开复算（`sample_n == 1`）→ 用自报值；低于 `guards.confidence_review_min`（默认 0.5）
  → `review_flag=True`（理由「自报置信度低于门限」）→ **必停**请人复核。
  开复算（`n > 1`）→ 多数票占比，自报值不参与。
- **不可用的单次回复**（无 content / 解析不出 / 标号越界 / provider 报错）改判为
  **请求失败** → 有界重发 `solve/solver.py::SAMPLE_RETRY_MAX = 2`（每条采样项最多 3 次请求），
  **不是**复算；**显式空作答是模型的结论**，不重发。
- 为什么：不开复算时只有一次采样，那个 1.0 的一致率不含信息；一次网络抖动/截断就会
  让 `chosen_labels=[]`，用户看到的是「模型解不了这道题」，真因只是那一次回复坏了 ——
  开复算时第二个样本能顺手救回来，所以这个故障**只在不复算时暴露**。

### ④ 动作回读是三态

- `act/verifier.py`：`region_change_state(mad)` → `changed`（`>= REGION_CHANGE_MIN_MAD = 2.0`）/
  `weak`（`>= REGION_CHANGE_WEAK_MAD = 0.05`）/ `none`；`verify_region_changed` 的
  `ok = state in {"changed","weak"}`，`actual` 形如 `region_mad=0.31 state=weak`。
- `act/actuator.py::select_option` 按**落点**分档：`ink_centroid` 落点 `none` →
  **绝不重点**（`ok=True`，readback `no_change_on_ink:...`）；几何兜底落点 `none` →
  换下一个候选点（换点前先重测）；全部候选 `none` → `_exhausted`（`ok=False` + 截图 + pause）。
- 为什么：画面本来就没什么可变时（纯文字行、或这道题**本来就已经选中**），旧判据判「没点中」，
  于是反复换点、乱点一气；多选上那一下会把刚选上的勾**取消** —— 重复点正是用户报的「胡乱操作」本身。

## 补记（同一天收尾时又补掉的五个真问题）

这一批测试逼出来五个问题，都已修 + 已钉用例（详见
`.workbuddy/artifacts/AutoLearn-P21开局判定与置信度收口-2026-09-30.md` §6）：

1. **`_plan_run` 丢掉开局那一次读图的首屏第 1 题**（`_read_question_by_vision` 只把其余题入队、
   第一道是返回值）→ 「一屏多题」时首题**静默跳过**，单题屏被**读第二遍**。
   现在 `insert(0, …)` 放回队首（与 `_scroll_reveal_next` 既有约定一致）。
2. **整卷提交后其余题停在 `applied`（不是终态）**→ 续跑会**重做**（多选题上重新点选项 =
   取消已选）。现在提交确认后 `_settle_paper_batch()` 把这一轮其余 `applied` 的题按
   `applied → submitted → verified` 推终态；**提交失败/暂停时不推**。
3. **「只有 page 观测、没有题目」的开局屏拿不到方案**：观测改在**解析成功**时就记。
4. **提交框第三个来源 `_last_submit`**（最近一次读图那屏的框）：关掉开局判定 + 每题提交
   原先必然 `vision_no_submit_box`；排序 `PAPER → [方案, 收尾, 最近]`、
   `QUESTION → [方案, 最近, 收尾]`，**框与尺寸永远同源**。
5. **解题请求带图的硬闸**（`Solver._complete`）：带图直接 `RuntimeError`（用户要求
   「解题组严禁拿到非文本输入」）。真机上发图会让推理模型**不回答、只烧 token**，
   从输出上完全看不出来 —— 所以要用硬闸，不能靠「记得别加」。

**测试侧同时修掉两条替身失真**（都在 `tests/test_vision_read_flow.py`）：
假页面用两个布尔量表示「已点选项 / 已提交」，看第二道题时它们已经是 `True` →
第二道题的点击被读成 `no_change_on_ink`、第二次提交被判「画面没变」；改成**累积状态**后

`(run_id, state)` 覆盖索引带成**状态字母序**（一屏两题时给出 `['failed','verified']`，
顺序正好反着），加 `ORDER BY rowid` 修正。
