### 真机暴露并修掉的 4 个缺陷（单测全绿也照不到）
1. **弹题遮罩挡住暂停路径**（产品 bug）：`.cs-interrupt` 是 `position:fixed; inset:0` 全屏遮罩，
   正好盖住播放按钮 → `MEDIA_LEVELS` 的 L1 点击**必然超时 3s**，而视频**仍在播放**
   （实测 1.50s → 4.02s）→ 「挂起期间必须显式暂停」根本达不成。
   修复：新增 `PAUSE_LEVELS = (L4 键盘, L2 脚本, L3, L5, L6, L1)`；
   `MEDIA_LEVELS`（播放）一字未改。实测三种路径：L1 超时 / L4 成功 / `evaluate("video.pause()")` 成功。
2. **提交级限速把回读的证据窗口睡过去**：原顺序「提交 → `sleep_submit_gap`(5~15s) → 回读」，
   而靶场弹题面板提交后 **400ms** 就被移除 → 一路判 `submit_timeout`。
   修复：改为「提交 → 回读 → 限速」。
3. **ε 兜底比 `ended` 早**：`currentTime ≥ duration − ε`（ε=0.35s）抢跑同刻到达的弹题
   （`?interrupt_at=end` 用例里弹题从未被检出）。修复：该判据改为**待定** +
   `ENDED_GRACE_S = 1.0s` 露头窗。
4. **`_await_human` 拿到决策后不放行运行闸**（**P7 存量 bug**）：用 `_pause_for` 清了闸，
   拿到决策只 emit 不 `gate.set()` → 半自动「确认一次、停一次」。P7 没发现是因为用例与跑批
   都在写库后显式调了 `resume()`。修复：决策即放行（只认自己造成的 `needs_confirm`）。

### 三个必须记住的坑（全部实证）
1. **注入 DLL 与 Chromium 沙箱冲突 → WebView2 空白窗口**（本次最大坑）。
   症状：窗口弹出但空白；uvicorn 收到 GET / 200 但无 css/js 后续请求；CDP 看 DOM 为空、
   readyState=complete；`data:` URL 能渲染，任何 http 不能；崩溃 dump：msedge.dll 内
   STATUS_BREAKPOINT(0x80000003) 同地址复现。根因：本机注入 GUI 进程的第三方 DLL
   （WPS Office `qingnse64.dll` 16MB 全局注入、WorkBuddy 沙箱 `tsbx.dll`）与沙箱子进程机制冲突。
   修复：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--disable-features=CalculateNativeWinOcclusion --no-sandbox`
   （须在环境创建前设置；WebView 只渲染本机自有 UI，关沙箱风险可接受）。
   **排障利器：pywebview `settings['REMOTE_DEBUGGING_PORT']` + playwright connect_over_cdp 页内取证**。
2. **关窗后进程不退**：pythonnet/CLR 参与后解释器关停挂起/极慢（10s+），端口仍占用。
   修复双保险：`window.events.closed += lambda: os._exit(0)`（FormClosed 同步触发，先于慢收尾）
   + start() 返回后兜底 `os._exit(0)`。注意：此钩子会让「窗口关闭后的代码」永不执行。
